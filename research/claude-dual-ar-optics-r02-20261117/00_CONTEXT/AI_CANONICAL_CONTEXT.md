## 4. 红线与证据分类
- E0 = 原厂书面确认/已核对版本的原厂手册；E1 = 工程文件和可复现本地检查；E2 = 第三方托管/媒体/逆向；E3 = 理论计算/方案推断；E4 = 未知、待供应商回复。
- **禁止用 E2/E3/E4 冻结生产设计。** E1 不等于实物 E0；在 EVK/样机测试之前不得宣称点亮/寿命/热验证完成。
- JBD 缺失的针序、VCOM/AVDD 电源、复位时序、指令码、dummy 周期、灰阶、背板版本一律保持 `TBD-JBD`。
- 源文档里的 `VERIFIED（第三方托管）` 只能表示“Claude 看到了二手资料”，不能转译为“JBD 已确认”。
- 任何变更先独立分支 + ECR ID + diff + 可重放检查 + 评审，不覆盖既有文件、不降低原规则。

## 5. 状态枚举
`PROPOSED`（建议）→ `EVIDENCE_PENDING`（缺资料）→ `DESIGN_APPROVED`（评审批准）→ `IMPLEMENTED`（文件真的已改）→ `STATIC_CHECKED`（ERC/DRC/CI 有日志）→ `BENCH_VERIFIED`（实测有原始数据）→ `CLOSED`。
任一阶段失败或证据缺失转 `BLOCKED`/`OPEN`，不能跨级报完成。
