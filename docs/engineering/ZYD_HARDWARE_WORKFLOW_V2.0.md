# ZYD Hardware Engineering Workflow V2.0

- 项目：智元跃动 AI/AR 智能眼镜 V1.0
- 状态：新工作流规范（待实施验证）
- 初始工程基线：EVT-1 H03 R11-MASTER，GitHub PR #64，NOT FOR FAB
- 仓库：https://github.com/yfei7131-source/AI-AR-codex-Claude-
- 产品约束：40 g 为整机研发目标；真实双目透明 AR；高密度集成；不降低既定电气、安全及制造规则。

## 1. 研发原则

工程结果优先、全局设计优先、批量执行、单一任务负责人、增量继承、分级验证、里程碑归档。按功能模块闭合、制造阻断解决及验证证据考核进展，不以文件数、版本数或 DRC 数量单独考核。既有有效成果复用；允许有依据的受控 ECO 和局部重排，不推翻工程或擅改产品需求。可执行候选与实际原生工程修改必须明确区分。

## 2. 技术设计路径

系统架构 → 结构/封装/制造可行性联合验证 → 电气设计及原理图 → 全局布局与可布线性评估 → 关键器件逃线及电源设计 → 全局批量布线 → 局部布线优化 → 完整工程验证 → 打样。

路径允许依据阻断证据返回对应环节，禁止在已知不可行的布局上持续盲目布线。P0–P7 是对当前项目的恢复及执行阶段，不是对已经完成的 H01–H03 工作重新编号。

## 3. 阶段门禁（P0–P7）

| 阶段 | 任务与交付 | 通过条件 |
|---|---|---|
| P0 研发流程与历史成果审计 | 复用 R11 STATE、历史有效结论及差异，建立唯一基线、阻断台账、任务归属 | 基线/版本/待解决问题/负责人明确；历史结论有出处；无需重复全仓扫描 |
| P1 EDA Skill 及开源工具能力对比 | 实测 easyeda-agent V1.20.0 目标版本及实际各组件版本；验证原生读写、布线、过孔、规则、保存、回读、回滚、批量调用；比较有价值的外部工具 | 安装与版本证据、代表性任务基准、能力/限制矩阵、可执行工具链明确；不能仅以安装成功代替测试 |
| P2 三板全局可布线性评估 | 布局拥塞、网络分类、可用层、孔跨、禁布区、铜面、供电、连接器和光机包络；列出根因及 ECO 决策 | 三板可布线性方案；关键约束与待外部确认项明确；试布证据支持路线决策 |
| P3 器件布局与逃线优化 | 原理图/封装冲突受控 ECO；关键器件扇出、供电骨干、回流、连接器及必要布局重排 | 原生工程验证关键路径可行；网络及规则保持；不可确认的物料/制造事项仍标 BLOCKED |
| P4 全局批量自动/半自动布线 | 按网络约束、功能模块及批次执行；先隔离试布，再接入主工程；保存并检查回归 | 规则受控、有效网络闭合、无新增未授权电气或制造违规；可重放及回滚；未完成项明确 |
| P5 局部布线及电气优化 | 补齐残余网络，优化 SI/PI、回流、热、RF、机械干涉 | 必需连接全部闭合，无未解释网表差异及错误；剩余风险明确转入验证 |
| P6 完整工程验证 | 完整 ERC/DRC/网表、DFM、制造能力、BOM、封装、光机/结构、重量预算、安全审查；独立重导入 | 无未关闭的投板阻断；有必要的板厂/供应商确认；任何豁免须有真实工程依据和授权 |
| P7 打样 | 冻结授权版本，制造包、BOM/CPL、装配方案、测试计划及样机验证 | 用户批准投板；打样后执行实物 Bring-up、功能、功耗、热、光学与安全验证 |

P0/P1 可并行；P2 可在工具评估期间利用已有可靠数据开展。P3/P4 前应具备相应约束与可行性证据；外部待确认事项可隔离推进无依赖任务，不得标为通过。P6 投板门禁不可绕过。

## 4. Agent 与工具架构

ChatGPT（研发决策、提示词审查、基线和任务管理）→ 统一任务与基线 → Codex（唯一主工程执行负责人）；Gemini（专项求解与研究）→ 可执行工程增量 → Codex；KIMI 仅在 Codex 不可用时接管主工程执行权。研究分支不得直接覆盖主档。交接须记录 commit、STATE、未完成任务、工具状态及回滚点。

ZYD-EDA-Execution Skill 是拟建立的项目级执行规范/编排层，不是已安装或已开发完成的插件。底层优先复用 easyeda-agent、EDA Agent Connector、可用的布线算法、HDI DFM 检查器、增量接入工具及自动门禁。嘉立创 EDA 专业版为原生工程执行与验证环境。V1.20.0 为 easyeda-agent 目标版本，CLI/Daemon/Connector 版本应分别以实际证据核实；不假定它们的版本号相同。上游 Skill 暂不二次开发。先完成能力测试，只有确认工具缺口才增加适配层或替代工具。

执行链：版本/连接检查 → 读取最新 STATE 与指定工程数据 → 分类网络/制定执行批次 → 隔离执行 → 局部验证 → 通过则接入主档、失败则回滚 → 按风险执行回归 → 更新 STATE、提交 GitHub。所有自动布线输出必须经原生规则和网表校验；离线 DFM 不替代板厂签核。失败方案按工具版本、工程基线、根因记录，条件未变不得盲目重试。

## 5. 统一任务单与提示词

每轮使用固定公共规则，只下发任务差异。建议字段：

```yaml
task_id: P2-PCB1-001
stage: P2
owner: Codex
baseline: <verified commit SHA>
scope: <board/module/net class>
objective: <engineering outcome>
inputs: <required paths and constraints>
allowed_changes: <scope and ECO authority>
acceptance: <measurable gates>
validation_level: local | batch | milestone
deliverables: <native changes or executable patch + evidence>
stop_conditions: <external dependency / tool failure / risk>
```

提示词：继承指定 commit 的最新 STATE 和任务相关数据，不重复审查历史。直接执行任务，优先解决根因及批量闭合功能模块。允许受控 ECO，不得降低制造/电气/安全规则。按对应验证级别检查。交付真实原生工程增量或明确标注的研究候选、必要证据、阻断及 Git commit；无实际进展不得宣称完成。失败时只尝试有新依据的替代方案，无法推进则记录根因并转交无依赖任务。提交前回读目标分支和工程文件。

## 6. 提示词发布前审查（100 分）

| 维度 | 分值 | 关键问题 |
|---|---:|---|
| 目标明确性 | 10 | 到底解决什么？ |
| 工程基线 | 10 | 是否继承最新有效成果？ |
| 任务唯一性 | 15 | 是否与其他 Agent 重复？ |
| 执行可行性 | 15 | Agent 是否具备真实操作能力？ |
| 技术路径 | 15 | 是否解决根因？ |
| 工程产出 | 15 | 是否有真实增量或可执行候选？ |
| 验收标准 | 10 | 如何判断问题真正解决？ |
| 输出效率 | 10 | 是否存在无必要输出？ |

建议门槛：90–100 分直接发布，80–89 分修改后发布，低于 80 分重拟。无有效基线、无执行能力、任务冲突、无验收条件、擅自降规或绕过安全门禁，任一项触发即拒绝发布，不以总分抵消。该阈值为新规范建议，非历史实测结论。

## 7. 分级验证

| 项目 | 局部修改 L1 | 批量修改 L2 | 里程碑 L3 |
|---|---|---|---|
| 受影响网络、已有连接保护 | 必须 | 必须 | 必须 |
| 目标板原生 DRC | 必须 | 必须 | 必须 |
| 相关 ERC/DFM | 按变更范围 | 必须 | 必须 |
| 三板完整回归 | 风险触发 | 风险触发 | 必须 |
| 独立工程重导入 | 风险触发 | 主工程接入时 | 必须 |
| 完整 ZIP | 不常规要求 | 不常规要求 | 必须 |
| 详细研究报告 | 不常规要求 | 不常规要求 | 必要时 |

叠层、全局布局、网表、安全电路或工具版本变化触发 L3。失败回滚后验证受影响对象恢复。每批比较真实原生违规对象及网络，不仅比较总数，禁止通过删网、改规则或错误豁免减少计数。

## 8. GitHub 与输出

统一以最新经验证接纳的工程 commit 为基线，不假定默认分支就是最新硬件。研究独立分支；原生主工程单一写入负责人；按功能批次提交真实工程文件和 STATE，阶段里程碑完整 ZIP 及原始证据归档。研究候选不能标记为原生验证通过。保留回滚检查点，不覆盖历史，不上传密钥、缓存和无关产物。未经授权不合并、不投板。

建议 STATE 仅记录基线/当前 commit、阶段、任务、关键约束、当前原生指标、已解决项、阻断及证据路径。Agent 输出：

```text
基线：
实际修改：
已解决问题：
连接错误：修改前 → 修改后
ERC/DRC/DFM：
实际执行耗时：
剩余阻断：
GitHub Commit：
下一步：
```

未运行的验证写 NOT RUN；不可解决的外部依赖写 BLOCKED；耗时未知则写未记录，禁止编造。

## 9. 效率与异常处理

每批记录有效网络闭合、功能模块闭合、制造阻断解决、新增回归、实际耗时、候选接纳/返工情况；比较相同口径下的真实工程效率。首次失败先判定是工具、数据、规则、布局、器件还是外部依赖问题；下一次试验必须有新假设、方法或输入。若仍无进展，暂停该路径、记录阻断并重新分配，不重复生成同类报告。未经验证不得承诺全自动布线可用或固定错误下降配额。

## 10. R11 过渡执行

R11 为当前已知原生归档（PR #64，非本规范独立 EDA 实测）：PCB1 322、PCB2 227、PCB3 127 个连接错误，合计 676；6 项严重 ERC、1 项 PCB1 网表差异；NOT FOR FAB。原生自动布线曾出现约 1.96–1.97 mil 线宽或无进展；不能直接沿用。

建议立即进入 P0 增量收口 + P1/P2 并行。Codex 负责 V1.20.0 真实环境基准和三板原生数据采集；Gemini 分板解决 PCB1 电气/封装/供电（含 U12、J2/J3）、PCB2 电源/去耦及光机约束、PCB3 WLCSP/HDI 逃线，并可设独立窗口研究批量布线算法及板厂工艺。分工以互斥任务单为准，不重复研究。KIMI 待命。P2 后按证据批准 P3 受控 ECO/重排，再进入 P4，不继续以小规模 R12 布线为默认目标。

外部阻断包括连接器实物与针序、0.80 mm HDI 叠层/二阶孔工艺确认、光机与结构、整机质量实测等。仍需实际验证 Skill 组件安装与能力、评估工作流效率，并将本规范由用户授权后同步到仓库。此文件未修改 GitHub、未安装 Skill、未执行 EDA。
