# 开发板到AR样机的硬件架构审查

日期：2026-11-10。当前范围是子系统边界、接口核对项与实测顺序；没有设计最终 PCB、指定未经核实的 GPIO、锁定 BOM 价格，或声称硬件已点亮。沿用 `ARCHITECTURE.md` 的 M0–M4 分层，AR 光学显示为 V1 P0。

## 系统与职责

```text
物理按键 / 相机供电与指示联动 / 麦克风
                   │
     [ESP32-S3 + PSRAM 开发板]
       │ DVP/JPEG相机    │ I2S/PDM音频 + 独立音频功放
       │                │
       ├ BLE控制/小数据 ──────────────┐
       └ 经实测选择JPEG数据链路 ──────┤
                                  ▼
                         [手机App / API中枢]
                                  │ 显式同意的HTTPS
                                  ▼
                         [云视觉/OCR/ASR/TTS]
                                  │ 结果/状态
                                  ▼
               [Halo等开发平台 或 独立显示控制模块]
                                  │ 厂商确认的接口/初始化
                                  ▼
                     [微显示 + 光学引擎 + 处方插片]

[受保护电池/充电/路径管理/NTC] → 各受控电源轨
[独立蓝牙通话音频方案，待选型] ↔ 手机通话路由
```

实线是计划的数据职责，不代表这些硬件已经连接。M0 现有浏览器摄像头只用于软件链路；M1 用开放SDK平台验证真实显示；M2 用开发板验证自有采集与电源。M1与M2可独立推进，整机集成需满足所有接口门槛。

## 已核验的官方事实与本项目推论

1. ESP32-S3的ESP-IDF蓝牙栈仅支持Bluetooth LE，不支持经典蓝牙。**工程推论**：F03不能由“ESP32-S3 + I2S”直接判定满足，需单独选通话音频链路并实测手机系统路由。[Espressif Bluetooth Overview（v5.2）](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32s3/api-guides/bluetooth.html)
2. 官方 `esp32-camera` 驱动列出ESP32-S3与OV2640支持；除低分辨率JPEG特定情况外要求PSRAM，且提醒RGB/YUV与Wi-Fi并发的内存压力。**工程决策**：优先带PSRAM开发板、单次JPEG，固定驱动版本后测并发，不把最高分辨率当作可持续帧率。[Espressif Camera Driver](https://github.com/espressif/esp32-camera)
3. ESP32-S3有两个I2S外设；PDM↔PCM硬件转换能力依端口，不能任选端口假设等价。**工程决策**：Pin Map同时登记音频模式和I2S控制器号，实测相机/无线/音频并发。[ESP-IDF I2S](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/i2s.html)
4. 官方S3 LCD文档列出SPI/I2C/I80/RGB路径，显示控制面和像素数据面需分别匹配。**工程决策**：DVP相机输入不等于MIPI DSI显示输出；任何微显示/光波导需厂商明确兼容的控制器或桥接模块，不能仅据通用`esp_lcd`描述画出直连。[ESP-IDF LCD](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/lcd/index.html)
5. 官方原理图指南对单路S3供电建议3.3V、输出能力不少于500mA，并提示内存占用GPIO等约束。该值不含本项目整机所有外设，**工程推论**：不可把它当电池平均电流/续航或整机稳压器定额；电源树按并发峰值复核。[Espressif Schematic Checklist](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html)

以上核验日期为2026-11-10；具体驱动/SDK工程接入时仍需锁定版本。仓库原有开源清单是参考入口；未核验具体版本LICENSE前不复制第三方工程文件。

## Pin Map与显示接口冻结门槛

当前不分配GPIO。下一轮按实际开发板官方原理图逐项填：主控/模组引脚→开发板GPIO→FPC序号→外设电平→上拉/下拉→复用冲突→启动绑带/Flash/PSRAM占用→测试点。相机时钟、麦克风、功放、USB、BLE/Wi-Fi共存、BOOT/RESET与摄像指示全部纳入；板号或模组变化后重审。

显示供应商须提供可验证的接口/初始化示例、分辨率与像素格式、亮度/功耗、电源时序、光学尺寸/眼盒/出瞳、中文路径、开发者许可及维护条件。无这些资料时继续独立显示平台验证，停止最终主板布局。

## 从开发板推进的验收顺序

1. 板卡/摄像模组/线束型号与许可证核查，通过官方JPEG例程；保存非敏感计数、故障和时延证据。
2. 实现物理按键、联动指示、停止/故障处理；检查相机实际活动与LED波形。
3. 测单帧传输与手机接收；补分片/重传/断连恢复；服务端真实AI/HUD沿用现有API。
4. 音频单独验证，再测相机/无线/音频并发；F03通话链路单独过手机实际通话验收。
5. Halo官方emulator验证Lua/按钮；中文采用主机栅格化；随后实机证明摄像采集到光学HUD，不以浏览器预览替代。
6. 取得电源/温升/续航/结构与配镜数据，完成BOM与Pin Map、电源树、原理图评审、KiCad ERC/DRC后再考虑PCB；制造输出仍按 `hardware/PCB_CHECKLIST.md` 全项门槛执行。
