# KIMI 工程交接 · EVT-1 H01–H05 · NOT FOR FAB

受控源为 PR #25 的 `97ee1f6733416099f842dca00389ab50f3568c96` 加本目录的已审查电气增量。三块板从各自的 `.kicad_pro` 打开，保留本地符号库与分层页面。用 `Inputs/effective_netlist.csv`、`Inputs/effective_bom.csv` 与连接器清单逐脚核对，区分板端触点、FPC 透传和供应商端引脚。标为 BLOCKED 的封装需要受控图纸和焊盘复核后才能落板。

1. **H01 电气输入**。核对各 SoC 电源与回流、电池保护、板间转换器、FPGA 配置方向以及 AVDD 监控与探测节点。先交回有证据的网表更改与 BOM 来源。未经审核的同类器件替代一律停在候选。
2. **H02 原理图**。按图面已标记的设计边界区分镜腿主板、鼻梁光学桥和右侧音频板。未知的相机、充电触点和波导/光机接口按阻断登记表处理。交回原生工程、各板原生网表与真实 ERC JSON，列明任何已知差异。
3. **H03 PCB**。先按分板约束完成尺寸包络、连接器配对、引脚 1、转接板位置、阻抗层叠和高速回流评审。AVDD 监测、开关电源环路、射频禁布、FPC 铰链动态区和两眼走线需分别给出可测规则。提交 `.kicad_pcb`、原理图、工程设置、规则文件及厂商能力证据。不得降低制造规则以清除 DRC。
4. **H04 光机与装调**。保持双目显示和透视路径。JBD AVDD、FPC 物理映射、初始化及分眼要求从厂商受控资料取得。CAD 仅预留两眼位置，待供应商 STEP、眼盒、入耦容差及装调数据齐备后决定几何。
5. **H05 验证**。保存 ERC、DRC、连通性与原理图/PCB 一致性日志，列出软件版本、工程提交、规则及排除项。台架计划记录探点、工具、工况、预期与实测结果。仿真结果按其验证范围记录，无法执行的阶段保留 BLOCKED。

回传时保留三块板各自的工程根文件名，并提供返回提交、文件 SHA256、封装来源与计划偏差。使用 `python tools/review_kimi_return.py <返回工程根目录> --output <独立证据目录>` 对实际返回运行原生 ERC 及带原理图一致性检查的 DRC。另须对照本目录的板间约束、制造规则和供应商阻断逐项复核。GitHub Draft PR 中的版本化工程包即为交接输入。
