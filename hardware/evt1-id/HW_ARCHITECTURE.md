## 2. 主控、音频与可复用软件边界

| 方案 | EVT-1 研究对象 | 复用入口 | 决策资料 |
|---|---|---|---|
| A | 左侧 S3 候选主控 + 右侧独立通话音频 + 两眼各自显示控制 | 既有 ESP-IDF、BLE v1/v2、有界 JPEG 和单帧授权逻辑可作为移植输入 | 实际板体积、全场景电池侧功率、显示桥能力、无线共存与热 |
| B | 左侧其他可穿戴主控候选 + 右侧独立通话音频 + 双目显示 | 保持手机/显示/采集合同；新平台需完整移植评估 | SDK/开发权限、驱动/授权、可获得样件、工具链、体积与功耗 |

S3 已有事实仅属于 [EVT-0 profile](../../firmware/main/board.c) 和 [R3 状态](../evt0-r3/H01/R3_STATUS.md)。EVT-1 没有冻结 S3 或 BM83 为生产选型；R3 的 GPIO、三针 J7、LDO 和 J4 占位不得直接复制为可穿戴接口。若更高集成方案改变已分配的右侧独立音频模块，须形成明确的架构/外观变更，不静默合并。

```text
                             iPhone / 已获同意的 AI 服务
                              │                 │
                     BLE / 有界媒体候选    HFP/A2DP目标
                              │                 │
  鼻梁相机 ─ 受控数据/供电 ─ 左主控板 ─ 状态/控制 ─ 右独立音频板 ─ 麦/开放式扬声器
    ▲                         │       │            │
  独立隐私联锁          左显示控制    右显示控制    右侧IMU
    │                         │       │
  外向可见指示             左光机    右光机
                              │       │
                           左波导    右波导
```

连线表示待冻结的功能责任，不指定总线、针序、轨电压或物理连接器。主控与音频之间要有独立设备身份、能力/状态、请求关联、超时/撤销和恢复查询；不能把 ATT 写确认当作接听/挂断成功。iPhone 同时使用两条无线链路与媒体时的路由、抢占和重连均待实测。高算力推理继续优先分配给手机/服务端；存储与同步行为保留用户同意和删除边界。

## 3. 鼻梁相机与故障安全隐私

EVT-1 不复用 R3“LED 并接相机轨”作为故障安全证明。[R3 电气审查](../evt0-r3/H02/evt0_core/ELECTRICAL_REVIEW.md)已记录该灯开短路时仍可能供电。新方案需要在原理图前给出以下**待验证合同**，器件拓扑保持 TBD：

| 状态 | 必须实现的硬件行为 | 必须记录的证据 |
|---|---|---|
| 无授权/上电/主控复位 | 相机电源与有效时钟/复位维持禁止；信号线无足以维持采集的反灌 | 冷启动、复位、欠压与断电的各轨/时钟/复位/漏电波形 |
| 请求采集 | 独立联锁先验证指示路径，再允许相机进入有效曝光/读出；指示覆盖整个有效采集期 | 灯光输出与曝光/有效帧/供电/时钟的同步记录；启动顺序及允许时延 TBD |
| 指示灯开路/短路/不可见、监视故障 | 不能证明外向可见即禁止采集；不得只检查 GPIO 回读或单靠 LED 电流 | 各单故障及遮挡注入；电流检测不足以证明遮挡后可见，需光路/检测方案证据 |
| 主控卡死/信号失联/供电故障 | 独立许可超时或监视故障使门控回到禁止；主控持续高电平不能无限保持许可 | 监视超时、锁存与清故障策略、最坏关断时延和在途帧边界 TBD |
| 用户撤销/后台/无线失权 | 撤销请求、停止采集并隔离数据路径；联锁仍独立兜底 | 协议撤销到电气关断的最坏时延；残留数据/在途帧处理 |

初步分块为：受限指示/检测支路、独立联锁监督、相机负载开关/放电、时钟/复位门控、必要的数据隔离。如何避免灯自检与相机供电相互依赖、如何验证外向光路、每路故障覆盖和故障后恢复都需单独电路评审，本文没有证明其中任何电路已有效。

当前全部 `privacy_interlock_verified=false` 保持原样。仅在选定样件完成 T11/T12 等价的电/光/单故障测试后，另提交与板号、相机及联锁版本绑定的已审 profile；本文件不授权解锁。

## 4. 双目光机、波导与配镜接口

M-OPT-L/M-OPT-R 各包括实际显示控制、微显示和投射光学，分别匹配 M-WG-L/M-WG-R。两眼是否共享显示源、帧同步和调光的实现均 TBD；双目几何、亮度/色彩、视差和延迟需独立校准。未知模块接口不能命名为已支持 QSPI/MIPI，也不能把单微显示器的公开参数乘二作为双目整套功率。

冻结输入必须包括：左右完整订货号与样件版本、光机和波导 STEP/机械图、光机到入耦区基准/公差、眼盒/眼距/瞳距范围、镜片与处方插片堆叠、颜色/亮度条件、供电/时序/峰值和待机功率、协议/SDK/许可、采购和可替代性。全部数值当前 **TBD**。

前框/铰链的机械包络先同时容纳双光机、鼻梁相机、FPC 与处方插片，再冻结板形；光学器件不能占用鼻托调节、镜片拆装或隐私灯视线。左右驱动过热、缺帧、失联和校准丢失时的关闭/降级行为待定义；不得通过移除一眼显示来静默满足功耗或空间。

Halo 和 [HUD 软件格式](../../app/hud_bitmap.py)可继续作独立台架参照。现有 [C sink](../../firmware/main/display_adapter.c)仅为已审 sink 的单张位图合同，未绑定光机，也没有眼别、双目同步或厂商协议。EVT-1 显示抽象另需定义眼别、帧/请求 ID、校准版本、亮度限值、有效期、取消/清屏与错误反馈；兼容旧合同不代表真光学测试通过。

## 5. 双侧电池、右尾 USB 与电源树

```text
右尾USB-C ─ 输入/ESD/故障保护 ─ 受控充电与电源路径（拓扑TBD）
                                ├─ 左独立充电/保护/温度监测 ─ 左电池模块
                                └─ 右独立充电/保护/温度监测 ─ 右电池模块

左电池输出 ─ 分路限流/反向阻断 ─┐
                              ├─ 受控系统母线 ─ 主控/音频/IMU/双显示各稳压支路
右电池输出 ─ 分路限流/反向阻断 ─┘                └─ 独立隐私监督 ─ 受控相机轨
```

这是要求清单，不是已选择电源芯片的接线图。双包的保护、温度、充电、故障电流与电源路径必须按实际电芯共同评审；**不直接并接未经评估的裸电芯/电池输出**。隔离指分路故障和反向电流控制，其具体拓扑、电气参考与是否需要额外隔离均 TBD；不能把两块保护板或一颗 R3 充电 IC 当作双电池安全结论。

需要明确：每包电压范围/容量/可用 Wh、允许充放电电流、NTC 特性与线序、两包不平衡/缺包/换包行为、充电与系统负载优先级、过温/断短路关断、共用母线回流、欠压与故障恢复。系统母线及分轨电压、电流能力、储能电容、升降压方案与焊盘均 TBD。R3 LDO 仅是 EVT-0 台架输入。

右尾 USB 的输入额定与协议、可用电流、数据/维护路径、连接器及密封结构均 TBD。维护可为实际 USB 数据延伸或经定义的服务桥，需按左主控选型决定，不能在没有完整链路时承诺烧录。充电中是否允许佩戴须经最坏温升评估；连接器应力不得传至电芯或铰链 FPC。

质量目标沿用用户输入：裸镜≤50 g、55 g 警戒；40 g 为挑战目标，处方版本另称。25°C 指定工况皮肤接触面≤41°C、4 h 不适≤2/10 为现有内部目标，均未实测。实际续航只按实测可用 Wh 与各场景电池侧瓦数/占空比推算，不用电芯标称容量或某颗芯片工作点替代整机数据。

## 6. 刚挠/FPC 冻结与全功能保留

详细接口逐项见 [INTERFACES.csv](INTERFACES.csv)。当前全部 `BLOCKED_TBD`，表示方向已分配、不能出最终针表/线束或生产板。每个跨铰链接口须给出接触面与 Pin 1、导体电流/回流、屏蔽/接地、端接/匹配、断电隔离、热插拔策略、SI/EMI、测试点与组装防错。FPC 静态/动态弯折区分别标注层数、铜型、板厚、最小半径、寿命与保持结构；这些数值均由实际供应商图纸和寿命试验给出。
