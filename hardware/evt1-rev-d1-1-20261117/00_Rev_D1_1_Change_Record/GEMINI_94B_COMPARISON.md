审查对象为 Gemini 内层 bundle 提交 `94b50cf66c149f0b5a613edd8e15f18cd2a0eb15` 相对 `bb876238fd25ac6be7c8f706b3d273b05d85a847` 的实际补丁，以及 PR #21 Rev D1 的 `ff7ccf93fb6ebce289e6a262adcea4e77c8d4928` 源树。没有把 Gemini 的旧 CSV 或“PASS”报告直接接到 Rev D1。

Gemini 的真实差异文件：`_archive_sync_20261117/pkg/delta/94b50cf_vs_bb87623.patch`，SHA256 `ffae081a5850b367e1626b9c62fd223318fae643aa688f26e44340f76e6268ff`。归档来源在远端分支 `archive/gemini-evt1-revc-94b50cf-20261117`。Gemini 增量**没有修改 RTL/PCF/TB**，其五状态叙述描述的是当时正脉冲接口，不能证明现行 Rev D1 电路安全。

## 1. 两套电路与信号的根本差异

| 项目 | Gemini 94b50cf | PR #21 Rev D1 |
|---|---|---|
| D3用户信号 | `frame_vsync_1v8`，空闲LOW、每帧HIGH1µs | `cdone_vsync_n`，空闲HIGH、每帧LOW1µs；OPT_PWR_REQ=0应使D3持续LOW |
| 配置中/失败 | 假定硬CDONE使D3持续LOW | 同样依赖硬CDONE；用户RTL测试不能模拟硬配置引擎 |
| 充电/保持 | D1整流+10Ω，经“驱动25Ω”假设给22nF充电；2.2MΩ泄放 | D3经100kΩ给220nF充电，DC-high保持 |
| 复位默认 | 改CRESET_B为10k下拉 | 桥板仍有10k上拉，主机侧100k下拉；跨电源域失电状态不能仅凭主机侧下拉推定 |
| 快速钳位 | 储能节点肖特基接CRESET_B和1V8轨 | 储能节点肖特基接CRESET_B |
| 旧“VSYNC丢失”覆盖范围 | 仅覆盖D3回到LOW、不再充电；不覆盖stuckHIGH | D3 stuckHIGH时储能节点永久有DC源，没有边沿看门狗 |

保留 Rev D1 的30针/5A跨板连接、电源器件、音频及光学数据通路；不回退到 Gemini 的旧24针连接和早期BOM。

## 2. 已复现的失效与旧计算缺陷

1. **Rev D1停止在D3=HIGH。** 直接RC在200ms时约1.7998V，此后趋近1.8V；没有任何电路能区分“正常帧间HIGH”与“时钟/扫描逻辑停止HIGH”。AVDD EN不会因缺少VSYNC而自动关闭。D3停止LOW则可经RC放电，这两个冻结相位必须分别测试。
2. **OPT_PWR_REQ的时钟依赖。** 旧D3只等于`~d3_low_q`，而该寄存器在48MHz域更新。主机写入断电请求后若48MHz停止，寄存器可保留HIGH；旧RC验证脚本直接假定物理D3已LOW，遗漏了这条失效路径。Rev D1.1的真实RTL故障台应验证主机域请求与停止时钟的组合，不能以本文件的电路模型代替。
3. **Gemini峰值保持不能识别stuckHIGH。** 正脉冲版若信号卡HIGH，或把它直接接到Rev D1的空闲HIGH信号，整流器持续充电，模型稳态约1.57997V。缺少边沿并不会触发其被动泄放。
4. **有限脉冲充电被不一致地忽略。** Gemini脚本对第一脉冲使用35Ω、22nF、1µs计算，却计算谷值时直接把每次峰值设为1.58V。用同样的参数、同时计入充电阶段泄放，精确周期固定点为峰值**1.42427V**、谷值**1.00936V**；第一帧谷值约**0.81416V**。其“1.12V谷值”不能由该参数组推出。以上35Ω与0.22V仍只是该归档的假设，不是原厂最坏值。
5. **LDO阈值错误。** 当前[TI TLV755P SBVS320D](https://www.ti.com/lit/ds/symlink/tlv755p.pdf)电气特性要求EN≥1.0V保证开启、EN≤0.3V保证关闭。Gemini使用0.95/0.40V。原峰值1.58V在零泄漏48.4ms时间常数下，衰减到0.3V需**80.41165ms**，并非按0.4V算出的66.48783ms。1.00936V谷值对1.0V仅剩约9.36mV名义裕量。
6. **容差/泄漏无保证。** 显式敏感性试算1.71V、C+20%、充电R+1%及泄放R−1%得到谷值0.98586V。另以+0.2µA净注入做敏感性试算，2.2MΩ泄放节点最终为0.44V，高于保证关闭电平。这不是声称真实器件必有这组参数，而是证明零泄漏/固定Vf不能被默认为原厂最坏值；必须有完整泄漏预算。
7. **快钳位时间没有依据。** Gemini的2.31µs来自3×充电35Ω×22nF；复位/电源轨钳位实际回路并不等于该充电电阻。钳位下限还包括驱动器VOL、二极管在该电流/温度下VF，以及复位/电源轨阻抗。储能可经钳位倒灌复位或掉电轨。未取得这些边界之前，不得把2.31µs或“断电反序已经消除”列为PASS。

## 3. 五状态的准确判定边界

| 状态 | Rev D1 / Gemini原方案结论 | Rev D1.1验收方式 |
|---|---|---|
| FPGA复位 | 在外部低阻钳位、Vf及VOL条件满足时可名义关断；默认/掉电阻抗未证明 | 检查真实复位默认、独立EN钳位的稳态负载边界；硬配置与板级动态仍BLOCKED |
| 配置失败 | 仅在硬CDONE确实保持LOW的边界下成立 | 物理引脚边界测试与用户RTL测试分开；不得把软件force当硅片实测 |
| 正常60Hz | D1的DC保持可运行；Gemini有限脉冲计算裕量不足且极性不兼容 | 保持原数据通路；检查独立边沿定时器最短时间大于一帧及正常1µs脉冲不触发误关断 |
| VSYNC/时钟丢失 | 两方案都遗漏stuckHIGH；Gemini仅名义覆盖回LOW | 分别注入HIGH/LOW冻结、无新边沿、主机断电请求，检查最长看门狗期限 |
| 1V8/VSYS掉电与瞬态 | 原二极管快关断数字没有最坏情况证明 | 通过两条供电监测与复位钳位证明受条件约束的稳态；电源快速斜率、欠压区间和实际AVDD放电期限继续BLOCKED |

## 4. 测试与BLOCKED范围

`05_Verification_Scripts/test_rev_d1_1_avdd_safety.py`独立复现上述RC和有限脉冲缺陷；读取单独硬件合同测试D1.1事件级边沿超时及钳位边界。`--require-ngspice`实际执行五个小型SPICE瞬态电路，保存原始deck与日志。它使用明确写出的理想固定Vf整流/驱动源模型，旨在核对拓扑与旧方程；**不冒充原厂晶体管模型或光机瞬态验证**。

本地初始未发现ngspice。官方[下载页](https://ngspice.sourceforge.io/download.html)所链接Windows47稳定包，两次下载返回HTML而非7z，未把它当有效工具执行。随后通过该官方页链接的[nightly工作流](https://github.com/gatk555/ngspice/actions/runs/43287024274)取得Windows二进制：MSVC版启动后因临时文件权限失败；MSYS/UCRT版因缺少运行时DLL失败。未将任一失败写成原生SPICE通过。Linux CI应安装真实ngspice并使用`--require-ngspice`；若缺失或执行失败则该阶段失败，物理安全状态继续BLOCKED。

即使计算/工具检查通过，以下仍必须BLOCKED：JBD AVDD精确电压、上/下电次序及允许残留电压；面板电流与输出电容；监控器无保证最大值的响应时间；实际I/O/钳位/关断泄漏、供电快速斜率及地弹；原生PCB/DRC和示波器故障注入。不能从“条件模型PASS”推导“所有电源瞬态安全PASS”。
