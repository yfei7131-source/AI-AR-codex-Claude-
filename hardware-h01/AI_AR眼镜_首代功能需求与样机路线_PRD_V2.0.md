# AI＋AR智能眼镜｜首代功能需求与样机路线 PRD V2.0

- 编制日期：2026-11-10
- 产品方向：L1眼前信息显示 + L2主动视觉AI理解（不包含L3空间锚定）
- 团队模式：独立创始人 + AI研发辅助 + 开发平台/外部专业供应商
- 当前阶段：产品定义与软件验证；芯片、供应商、价格、外观不冻结
- 本文所有性能/重量/时间为待验证的内部目标值，不是已达成规格或合同承诺。

## 1. 用户问题与产品承诺

主要问题：看到信息需要低头掏手机拍摄、输入、查询，再整理成待办；外语/字幕依赖手机；现有智能眼镜可能引发耳后、太阳穴与鼻梁压痛，近视验配也可能不便。

核心承诺：**看见 → 理解 → 眼前呈现 → 经确认执行**。在工作和生活中降低操作摩擦，同时以近视适配和舒适性作为强制门槛。

首代的「AR」包括头随动HUD文字、语音/翻译字幕和单次摄像头画面理解；**不包括**将图像或标签精确锚定到物体表面的空间追踪能力。

## 3. 三条首代核心体验链

### A. 即拍即问（L2视觉理解；最高优先）
1. 按键主动唤起取景；外部拍摄指示与状态提示生效。
2. 采集单张照片；屏幕短暂提示「正在识别」。
3. AI识别文本/对象并以2–3行返回答案；手机端保留来源与详细信息。
4. 识别不确定时显示「未能确认」并支持重拍。
5. 示例：设备铭牌、商品标签、外文路牌、技术说明书。

### B. 看见→行动（L2＋任务闭环；差异化优先）
1. 用户拍下标识或文字，语音说「把这个交期记下来，周五提醒我」。
2. OCR+LLM提取对象、日期、动作，生成待确认卡片。
3. 用户确认，手机实际创建任务并返回写入结果。
4. 用户可在App撤销、修改、删除；任何错误保持可追溯。

### C. 翻译字幕（L1＋AI；高频场景）
1. 用户主动开启翻译模式，并选择语言。
2. 语音/图文识别后分句显示在HUD，短字幕不遮挡真实视线。
3. 噪声、多人说话、识别失败时提示需核对；默认不保存他人语音。

## 4. 交互规则（不可跳过）

- **一按**：唤出/拍摄（具体操作映射待用户试验决定）；**长按**：退出或中止；**语音确认**：仅在显示确认内容后允许。
- HUD只显示关键词与短答；详细内容跳转手机。优先单目单色，不上全彩沉浸式界面。
- 状态机：待机 → 主动采集 → 处理中 → 结果 → [待确认] → 执行中 → 成功/失败 → 关闭。
- 危险操作、支付、对外发送、设备维修指令不得自动执行。高风险识别结果需资料/人工复核。
- 拍摄与录音状态必须清晰提示；产品量产阶段应审查外部指示灯是否可通过硬件与传感器采集链路绑定。

## 5. 工程架构（首代建议）

```text
[镜腿按键/麦克风/相机]──[设备端摄像与音频SoC]──(BLE控制 + 图像数据链路)──[手机App]
                                                                        │
                                                           [ASR/OCR/多模态LLM]
                                                                        │
                                                           [任务状态与权限引擎]
                                                                        │
                                                  [字幕/简答/任务卡/实际执行结果]
                                                                        │
                                        [手机App]──[显示通道]──[单目HUD光学引擎]
```

- 设备端：拍摄、拾音、按钮、显示与低功耗控制。
- 手机端：联网、图像压缩/传输、权限、任务持久化与系统接口。
- 云端：按需视觉语言模型、ASR/翻译、TTS；预留模型供应商切换机制。
- **传输门槛**：确认SDK确实允许第三方获取图像并发送到手机，BLE是否足够由文件大小/延迟测试决定；不默认可用连续视频。
- 单目光波导视场、眼盒、近视衬片与光学校准需专业供应商参与。禁止自称已掌握量产光学。

## 7. 研发优先级：一人开发的实际顺序

| 次序 | 里程碑 | 必须完成 | 不做 |
|---|---|---|---|
| M0 | 手机上的视觉AI闭环 | 手机相机→识别→短答→模拟HUD→任务确认 | 眼镜PCB、定制光学 |
| M1 | 真正眼镜上的单张图像闭环 | 开发平台相机图像→手机/云端→HUD真实显示；按键退出 | 录制连续视频、SLAM |
| M2 | 翻译与语音任务闭环 | 分句翻译、随手记、任务确认与写入、清晰状态提示 | 全语种无延迟承诺 |
| M3 | 舒适与配镜评估 | 不同头型试戴、近视样镜、鼻托与镜腿可调、耳后压痛对比 | 在无佩戴数据时开正式模具 |
| M4 | 自主工程样机候选 | 光学/声学/电池供应商选型、系统功耗、热、PCBA、结构 | 从零自研光波导模组 |
| M5 | 商业量产评审 | EVT/DVT/PVT、法规、良率、成本、售后与真实支付意愿 | 跳过认证直接销售 |

### 第一阶段参考节奏（非承诺工期）
- 0–2周：明确3条产品体验及测试数据集；完成手机App任务状态机。
- 2–6周：完成手机AI识别、OCR、HUD模拟界面、任务确认闭环。
- 6–10周：评估SDK与开发平台（条件允许时进行实际设备测试），集成图像传输和真实HUD。
- 10–16周：加入字幕、记录与佩戴/近视试验；收集延迟、重量、热与痛点数据。
- 2027年：依据验证决定外部合作完成光学、结构、电池和PCBA；如无供应商支持，不承诺一人独立完成消费级量产。

## 8. 验收指标（目标，需固定测试口径）

| 指标 | 初期目标 | 测试方法 |
|---|---|---|
| 单次图像问答成功率 | ≥90% | 100张预先选定图像，区分图片清晰度、光照、距离；按正确且可用的回答计分 |
| OCR关键字段提取正确率 | ≥95% | 50张清晰标签与铭牌；逐字段评分；不将模糊图计入同一分母 |
| 从拍摄到HUD短答的P95时延 | ≤6秒 | 固定Wi-Fi/手机/云服务条件下，至少50轮实测 |
| 任务创建成功率 | ≥99%（已授权且接口正常） | 100次重复测试，含幂等及失败提示 |
| 正常退出、失败反馈覆盖率 | 100% | 每一个功能状态都有退出与错误路径 |
| HUD易读性 | ≥90%试用者能在常用光照中读懂短答 | 眼镜实际佩戴、标准化内容与条件 |
| 佩戴舒适度 | 4h后耳后、太阳穴、鼻梁不适感≤2/10为初期目标 | 与个人常用光学眼镜比较，覆盖不同头型与近视镜片 |
| 重量 | 有摄像＋HUD裸镜优先目标≤50g，工程警戒线55g | 实测裸镜与验配整镜；不以裸镜代替真实重量 |
| 热与电池安全 | 目标接触皮肤表面在25°C环境指定工作负载下≤41°C | 连续取景/无线传输/显示分别测试，安全阈值按最终适用标准核定 |
| 隐私状态提示 | 采集过程100%可感知，用户可停止与删除 | 权限拒绝、断网、异常、取消的完整测试 |

这些阈值为内部起点。若功能无法稳定通过，应削减功能或调整架构，不能只通过宣传规避问题。

## 9. 采购决策门槛（先验证、后买设备）

1. 官方SDK确实支持第三方获取第一视角拍摄结果，并有设备端或手机端数据接口。
2. 官方SDK确实支持开发者控制显示内容和按钮事件，而非只能使用官方AI助手。
3. 能在中国目标网络、账号、手机系统环境中使用（逐项验证）。
4. 软件许可允许商业样机开发；产品化授权另行谈判。
5. 近视镜片方案与可佩戴性没有明显阻断问题。

**购买前要求运行或看到能复现的官方示例**：采集图像、显示字符、按键事件、手机端数据传输。缺其中任何一个，不作为本轮主开发平台。

## 10. 当前不做的事

- 不做L3全空间锚定、SLAM、全彩大视场沉浸式AR。
- 不承诺任何现实物体被永久跟踪或准确覆盖虚拟标签。
- 不做全天自动监听、隐藏拍摄、人脸身份识别或健康诊断。
- 不做自研光波导、芯片、基础模型。
- 不锁售价、不虚构供应商BOM报价、不跳过近视验配与用户舒适性测试。

## 11. 下一次产品评审需要回答的四个问题

1. 用户究竟会更频繁使用「即拍即问」「翻译字幕」还是「看见→行动」？
2. 在具体试戴条件下，相比普通近视镜是否能做到相近舒适度？
3. 有摄像头+HUD时，能否控制重心、厚度、热与续航？
4. 与现有成熟眼镜相比，我们的体验提升是否足以形成付费理由？

结论：**先做M0与M1的真实交互闭环，再决定是否将2027年作为量产目标。**
